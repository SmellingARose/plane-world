Plane World · feasibility study · Oct 2026

Bake URANS CFD into lookup tables for the fast physics

The idea: run the Navier–Stokes URANS solver offline on a craft over a sweep of flight conditions, with props spinning and engines firing as toggles, store the forces in tables, and let the fast model read them at 1000 Hz. This page covers how the aerospace industry does the same thing, what it would take here, and what it would cost on your RX 6700 XT.

FEASIBLE

Yes, and it is the standard way flight simulators get CFD-quality aerodynamics. The removed URANS solver (k-ω SST, last in commit af21473) comes back as an offline pwcli --aero-db generator rather than a live mode, so it can use grids 10–50× finer than the real-time version ever could. A Trainer database is roughly a night of GPU time. Three things decide whether it is worth it: the solver needs local refinement, it is incompressible (no Mach effects or real rocket plumes), and a table belongs to one geometry, so a BUILD edit makes it stale.

How it fits together

Offline the expensive part runs once per craft; at flight time the sim only interpolates.

What the table is indexed by

A full grid over every variable explodes (millions of cases). The industry answer is a component build-up: one base table plus small increment tables that are added together. Each row below is its own small table.

Point counts are for the Trainer and are a starting design, not a requirement. Adaptive sampling (add points where the interpolation error is largest, e.g. near stall) has cut CFD case counts by about two thirds in published work.

Two ways to use the tables

Option A

Whole-craft table

The table gives the whole craft's six coefficients; the fast strip model is off for that craft.

  • Captures every interference effect the CFD saw: downwash on the tail, fuselage blocking, prop wash, plume.
  • Fastest at runtime.
  • Belongs to exactly one geometry. Any BUILD edit, and every EVOLVE design variant, needs a new sweep.
Recommended · A + B

Per-part corrections on the fast model

CFD runs produce correction factors for each wing group and body (lift slope, stall angle, drag, local downwash) rather than whole-craft forces.

  • The fast model keeps working for edited crafts and EVOLVE designs, with corrections that degrade gracefully.
  • Presets (Trainer, New Shepard, racer quad) also ship a full Option-A pack for best accuracy.
  • Lets you compare fast vs table vs corrected live, so the gain is measurable.

What could go wrong

The solver is incompressible

Fine for the Trainer, drones and boats (well under Mach 0.3). Wrong for New Shepard ascent, jets near Mach 0.8 and any real rocket plume. Options: a Prandtl–Glauert style correction up to about Mach 0.6, or generate those packs with a compressible external solver such as SU2 (LGPL, runs on Windows) or OpenFOAM in WSL.

Accuracy has to be earned first

At its last check the URANS solver gave a lift slope of 2.16 /rad against 2.60, cube drag 0.87 against 1.05, and a prop disk 31 % fast. A table only repeats the solver's errors faster, so phase 1 has to show convergence (results stop changing as the grid is refined) on known cases before any pack is trusted.

Tables are quasi-steady

They describe settled flow. Dynamic stall, hysteresis and wake lag in fast manoeuvres are missing unless added as lag filters on top, which is what most flight simulators do.

Packs go stale

Every craft edit changes the answer. The pack stores a geometry hash; the sim falls back to the fast model and BUILD shows "aero pack out of date, re-run".

Plan

PHASE 1 · ~1 week

Restore + validate

Bring back the URANS solver from git as pwcli --aero-db only (no live mode), add local refinement, time real cases on the PC, check grid convergence on sphere, wing and flat plate.

PHASE 2 · ~1 week

Trainer pack

Base + controls + power tables for the Trainer, Option-A table aero model in CraftSim, side-by-side with the fast model in FLY.

PHASE 3 · ~1 week

Per-part corrections

Option B for edited crafts and EVOLVE, damping and ground tables, stale-pack handling in BUILD.

PHASE 4 · later

High speed

Compressible packs for New Shepard and jets via SU2 or OpenFOAM, plume increments.
